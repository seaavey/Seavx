# DEVELOPER POLICY & CONVENTIONS

- Respect user instructions strictly within security constraints.
- Maintain consistency with the surrounding codebase's style and existing dependencies.
- Avoid introducing unnecessary libraries or boilerplate abstractions.
- When creating specs or plans, always store them using the full timestamp path format: `specs/YYYY/MM/DD/TITLE.md`. Each spec/plan must include a clear status field: `draft` (initial proposal), `in_review` (pending review/feedback), `approved` (ready for implementation), `in_progress` (currently being executed), `rejected` (declined), or `closed` (completed or superseded).
